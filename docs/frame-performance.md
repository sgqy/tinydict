# 窗口性能诊断

## 当前启动策略

Intel UHD 630 + RDP 环境反馈 Vulkan 启动时发生 segfault。Windows 默认后端现为 Direct3D 12，macOS 为 Metal，其他系统为 Vulkan；失败后尝试 OpenGL。下文保留早期开发机的 Vulkan 性能结果，不能用这些结果推断 RDP 兼容性。

父进程不初始化图形驱动。每个候选后端在独立子进程中创建实际窗口；子进程进入第 3 个独立 UI 帧时报告就绪。就绪之前异常退出，或 30 s 内未就绪，父进程会尝试下一个后端。超时的子进程先终止并回收，用户正常关闭窗口则不触发回退。

`--renderer auto` 是默认值。`--renderer vulkan` 优先尝试 Vulkan，再尝试平台后端和 OpenGL，并去除重复后端。`--renderer glow` 优先尝试 OpenGL，失败后尝试平台后端。Windows 日志位于 `%APPDATA%\TinyDict\data\graphics-startup.log`。

自动测试覆盖子进程失败、就绪和超时回收；开发机已记录 Direct3D 12 渲染就绪。真实 UHD 630 + RDP 环境仍待复测。检测只覆盖启动阶段，就绪后的驱动故障会记录退出状态，不自动切换后端或重启。

## 早期长帧排查

2026-11-17 排查“鼠标在窗口内移动就卡，包括空白首页”。已将瓶颈范围缩小到界面构建之后的渲染、呈现和事件循环等待。鼠标移动会触发 egui 重绘，不会重新查询词典。首页与查询页的界面构建均远低于一帧的时间预算。

当时将 Windows 默认后端改为 wgpu / Vulkan，保留垂直同步和 1 帧的目标排队上限。正常模式仍按事件重绘。当前仍可通过 `--renderer vulkan` 复测该路径；`--renderer wgpu` 在 Windows 上选择 Direct3D 12。

2026-11-17，使用者在新版窗口的空白区域实际移动鼠标，反馈“已经明显顺滑”。这确认了切换 Vulkan 对本机实际操作的改善。尚未用系统级跟踪区分 OpenGL 驱动内部、桌面合成器和线程调度，也未测量真实鼠标到屏幕的延迟，因此不将原因归结为某个具体驱动缺陷。

## 测量方法

使用 release 构建、RTX 4080 SUPER 和 NVIDIA 621.14 驱动。两本完整词典均已加载。窗口为 1240 × 820 逻辑点，缩放比例为 1.5。垂直同步下，帧间隔中位数约为 8.33 ms。

`--profile` 等待加载与查询结束，预热 1 s，再持续重绘并记录样本。`--profile-motion` 每帧注入变化的 egui 指针位置。它覆盖悬停处理和绘制，不覆盖操作系统的高回报率鼠标事件队列。

分别记录三个时间：应用构建界面的时间、eframe 的帧 CPU 时间，以及两次逻辑更新之间的间隔。eframe 的 CPU 计时会扣除它识别的呈现等待。帧间隔包含事件循环、调度和呈现等待，不能等同于 GPU 执行时间或屏幕实际扫描时间。

## 观察结果

OpenGL 的长帧具有间歇性。早期首页与查询页测试捕获了约 35 ms～46 ms 的帧间隔；这些帧的界面构建约为 0.1 ms～0.2 ms。关闭 OpenGL 垂直同步后，仍捕获到约 41 ms 的长帧。后续 20 s 复测中，首页没有超过 16.7 ms 的样本，查询页有 1 帧达到 27.11 ms。单次短测无长帧不足以证明问题消失。

Vulkan 对照中，首页和 `computer` 查询页各采集 20 s，最大帧间隔分别为 11.99 ms 和 12.04 ms。两轮均未出现超过 16.7 ms 的帧。另一次通过窗口操作确认可见且在前台的首页测试持续 30 s，采集 3,599 帧：

| 指标 | p95 | 最大值 |
|---|---:|---:|
| 界面构建 | 0.090 ms | 0.280 ms |
| eframe 帧 CPU 时间 | 0.575 ms | 1.294 ms |
| 帧间隔 | 8.631 ms | 9.550 ms |

交付目录 `dist` 下的程序另做了一轮可见窗口测试，使用默认后端运行 20 s，采集 2,399 帧。帧间隔 p95 为 8.648 ms，最大值为 11.255 ms，没有超过 16.7 ms 的帧。报告为 `default-visible.json`。

自动隐藏启动的部分测试出现了 500 ms 或 1 s 的异常间隔，涉及 Vulkan 和 Direct3D 12。报告中的焦点标记仍可能为真，因此不能用该标记代替实际窗口观察。这些样本不用于比较前台性能；以后复测应让窗口可见，并确认未被遮挡。
